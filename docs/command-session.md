## What changed

- The factory owns both diagnostic objects privately; it exposes submission, update, hook forwarding, stop and an unsupported checkpoint operation. No direct punch request is handed to a listener. The opt-in runtime fixture uses this factory; ordinary diagnostic buttons do not.
- Requests name bounded session/encounter/phase/action/entity IDs, an observed revision, a caller-provided partial-state witness and explicit origin/target coordinates. The trusted harness supplies peer identity. This is not authentication; future transport must bind identity to its connection rather than trust a message's player field.
- A copied registry supports more than three entities, explicit commandability and ownership. The fixture includes Combat, Cannon, Artillery and the controllable Archive Artillery ally. An omitted or newly seen friendly stops admission. Registry inclusion does not claim adapters support that ally's actions; they reject it. A future test mission may exclude allies; the existing fixture cannot silently omit one.
- Duplicates never dispatch again. Reusing an ID with changed content conflicts. Busy/stale requests remain rejected even when replayed later: retain the UI draft, obtain a fresh preview and explicitly resubmit with a new ID. No auto-queue or retry. Records cap at 128 without eviction; reaching the bound stops this non-resumable experiment.
- Original profile/version/mission/phase, movement legality, UI-preview, one-move-per-mech and one-punch-per-process safeguards remain in the real modules. The punch remains actor 0 at (3,3), target 101 at (2,3), standard weapon slot 1 and the original effect/health checks. Unsupported payloads cannot choose arbitrary attacks.
- Guard failure, unmapped friendlies, uncertain dispatch, diagnostic timeout, update/hook errors or evidence failure stop both paths. The coordinator does not itself release protected input or reverse an engine action. Runtime wiring verifies the guard before admission, propagates lifecycle events, and calls native sessionStop on failures. Normal adapter cleanup retains protected blocking.
- Completion requires existing diagnostic hook/postcondition evidence. Revision advances after its pending action clears with that evidence. It means partial diagnostic observation, not a proved engine completion barrier or peer agreement.

Native C code and the tested DLL are unchanged. The scoped installer now includes the coordinator, End Turn adapter and opt-in fixture.

## Protected End Turn and admission boundary

End Turn uses the same bounded request records, peer allowlist, context/revision/partial-witness checks, pending slot and failure latch as movement and punch. Both trusted peers must confirm readiness for the same phase, revision and witness, including loss of unused actions. An admitted action clears readiness. Duplicate, stale, conflicting and unready requests never dispatch; uncertain dispatch is never retried.

The adapter clicks native End Turn and recognizes the observed unused-unit Active Units subpanel before clicking native Yes. It does not suppress the dialog or select Don't Ask Again. Calibration is restricted to this checkpoint, game 1.2.93, 1920×1081 and board scale 3. Unexpected geometry times out safely. One-pixel cursor rounding matches the existing bridge tolerance; after the independent button release, later draws let SDL process it before aiming at Yes. The path without a confirmation is allowed to enter the same phase hooks, but has no live evidence in this increment.

Admission requires this ordered sequence: PreEnvironment → PostEnvironment → enemy NextTurn → VekSpawningEnd → PreEnvPlanned → PostEnvPlanned → player NextTurn. Spawn notifications are observed without replacing these boundaries. Team and turn must agree. The final hook alone is insufficient: wait for a later real mission update and draw, an idle observed board, GetBusyState()==0, an empty loader runLaterQueue, and complete observations showing all four known surviving unfrozen friendlies active with unused movement. A 60-second timeout latches the protected session stopped without retry.

Pinned loader source explains this boundary: PlanEnvironment finishes before subsequent AI planning; BaseNextTurn fires its hook after the underlying transition; BaseUpdate processes runLater callbacks before the mission-update hook. Live evidence shows busy==0 repeatedly before completion. Neither idle nor repeated unchanged snapshots admits the next command. This is a conservative boundary for Mission_Artillery turn 2→3; it does not prove general engine quiescence, all missions, or hidden-state agreement.
